# AI 原生生灵：行业可落地解决方案白皮书

**版本**：v0.1 · 2026-09
**配套原型**：Monta NPC 自主营地（Unity）、QY 第三人称开放场景（UE5）
**配套论文**：`docs/paper.md`

---

## 摘要

"AI 原生生灵"（Native AI Lifeform）指一类**在虚拟世界中具备持续目标、能与同伴自主协商分工、在世界事件发生后自动重规划，且其核心决策链路不依赖大模型、可离线运行、行为可审计**的数字智能体。

本方案基于两个已验证的 Windows 功能原型（Monta 营地 demo、QY 第三人称场景），给出一套可直接交付给游戏、虚拟人、文旅、仿真训练、教育陪伴五个行业的落地架构、成本模型与 18 个月路线图。核心判断是：**LLM 负责"开放对话与创造性"，规则化自治内核负责"可靠目标达成与实时性"，二者通过适配器组合，而不是互相替代。**

## 1. 什么是 AI 原生生灵

传统虚拟世界里的"角色"有三种：

| 类型 | 驱动方式 | 典型表现 | 局限 |
|---|---|---|---|
| **脚本 NPC** | 状态机 / 行为树 | 走到 A 点说 B 台词 | 作者没写到的地方=空气墙 |
| **动画木偶** | 动捕 + 预排 | 影视级演出 | 不会自己决定做什么 |
| **LLM Agent** | 大模型直接决策 | 会聊天、会即兴 | 延迟 1–5 秒、成本高、行为不可预测、难审计 |

**AI 原生生灵**是第四种：

- **有持续愿望**（Desire）：例如"建成一座能住人的营地"，不是被玩家触发才动；
- **会自己拆目标**（Goal Graph）：把"建营地"拆成选址、伐木、采石、砌墙、上顶、捕宠、入住；
- **会和同伴商量**（Negotiation）：两个 NPC 用 ~20 秒语音协商谁去采集、谁先搭框架，而不是各干各的或由策划排表；
- **出事会自己改计划**（Replanning）：同伴受伤、资源点被封锁时，自动撤销当前任务、重算分工、休养后复工；
- **核心链路离线、毫秒级、可审计**：不联网、不调 LLM、不需要密钥，每一步决策都能回放。

> 与原型作者保持一致的立场：**这套系统在行为上"像活物"，但它不是、也不声称是有意识的主体。** 这一区分在对外宣传、合同、伦理审查中必须保留。

## 2. 为什么是现在

三个行业信号同时出现：

1. **3A / 独立游戏都在找"下一个角色叙事突破口"**。玩家对"走过去按 E 对话"已经疲劳，2024–2026 年多个开放世界项目的回放率下降与 NPC 单调直接相关。
2. **LLM 直接驱动 NPC 的生产事故已经出现**：延迟高导致战斗节奏断裂、成本不可控（一个 4 小时游戏内 NPC 对话成本可达数十美元/玩家）、幻觉导致剧情穿模。
3. **端侧小模型 + 结构化规划技术成熟**：BDI、HTN、GOAP 这些经典符号 AI 方法在过去五年被重新拾起，并与 LLM 的"语言理解"侧解耦，形成"大脑轻、嘴巴活"的可行组合。

Monta 原型在 2 分钟内、单机离线、零 LLM 调用的条件下完成了"选址→协商→采集→建造→事件重规划→交付"全闭环，证明这条路线**技术上已经成立**。

## 3. 总体技术架构

六层解耦，引擎中立：

```
┌──────────────────────────────────────────────────────────┐
│ L6 表现层   Unity / UE5 / Web / 数字人 / 移动端           │
├──────────────────────────────────────────────────────────┤
│ L5 协议层   gRPC / WebSocket · JSON 消息 · 事件总线        │
├──────────────────────────────────────────────────────────┤
│ L4 适配层   LLM Adapter（开放对话）· TTS Adapter（语音）  │
│            视觉 Adapter（表情/动作）· 不接时自动降级        │
├──────────────────────────────────────────────────────────┤
│ L3 自治内核  BDI · 目标图(HTN) · 协商协议 · 重规划器       │  ← 纯规则、离线、毫秒级
├──────────────────────────────────────────────────────────┤
│ L2 世界模型  状态快照 · 资源/库存 · 队友状态 · 事件队列     │
├──────────────────────────────────────────────────────────┤
│ L1 感知层   游戏引擎回调 · 传感器 · 玩家行为 · 环境事件    │
└──────────────────────────────────────────────────────────┘
```

关键设计原则：

- **L3 自治内核零 LLM 依赖**。生产环境断网、API 限流、成本超预算时，整个系统仍能跑。
- **L4 是可插拔的**。LLM 只在三类时机被调用：①玩家发起开放性闲聊；②需要即兴台词而行为树没覆盖；③剧情分支需要"创作一个新任务名"。其余 90% 决策走 L3。
- **L1–L3 全部可序列化**。任何 NPC 任意时刻在想什么、为什么做这件事，都能写成一行日志并在回放工具里复盘。

## 4. 五个行业落地方案

### 4.1 游戏行业：开放世界与社交 NPC

**痛点**：MMO 里 NPC 是"道具式商贩"，单机 RPG 里 NPC 是"一次性剧情触发器"。玩家留存与 NPC 多样性强相关，但策划手写行为树的成本随 NPC 数量指数上升。

**落地方案**：

| 模块 | 做法 |
|---|---|
| 主城生活 NPC | 给每个商贩/守卫/酒保一个 Desire（"开店""巡逻""找小偷"）+ 目标图，玩家离开视线后他们仍在自治运转 |
| 队友系统 | 类似 Monta 营地：2–4 个队友在副本外自主协商分工、共享背包、受伤时互相掩护 |
| 动态事件 | 用重规划器接住世界事件（商队被劫、酒馆斗殴），NPC 不是切镜头演出，而是真的改变行为 |
| LLM 边界 | 仅用于玩家与 NPC 的自由对话；战斗、寻路、分工、任务接取走规则内核 |

**成本参考**：一个 20 NPC 的中型主城，规则内核开发约 2 人月；LLM 对话调用按玩家日活估算，单 DAU 日成本可控制在 ¥0.05 以内（仅闲聊路径）。

### 4.2 虚拟人 / 数字人直播与客服

**痛点**：现有数字人"会说不会做"——台本播完就冷场，遇到突发提问靠人工切。

**落地方案**：

- 给数字人一个**本场直播的 Desire 集合**："讲解商品 A""回答弹幕问题""引导下单""在冷场时抛话题"。
- 规则内核负责**流程与节奏**：商品讲解顺序、停留时长、催单时机、合规词过滤；
- LLM Adapter 负责**即兴回应**：弹幕来了生成口语化回答，但所有回答在被 TTS 播出去之前过一遍规则层的合规审核。
- 事件重规划对应直播事故：商品断码 → 自动切到替代品讲解；弹幕带节奏 → 切到预设合规话术。

### 4.3 文旅 / 主题公园 / 博物馆

**痛点**：导览设备千篇一律，景区 IP 形象（玩偶、大屏虚拟人）不会"陪游客走完全程"。

**落地方案**：

- 一个"原生生灵"作为虚拟导游，**有自己的日程**：上午在入口迎接、中午在茶座"休息"、下午带研学团、傍晚在出口送客。
- 游客走近时触发协商式对话：根据游客年龄/兴趣（扫码或简单问答）决定讲正史还是讲野史。
- 与 IoT 联动：闭园广播触发"导游"说"今天要下班了"，而不是死循环播欢迎词。
- **完全离线部署**：景区网络差，规则内核跑在本地盒子，TTS 用端侧模型。

### 4.4 仿真训练：应急、医疗、军事、客服沙盘

**痛点**：仿真训练里的"受训对象"（病人、灾民、敌方士兵、投诉客户）反应僵硬，学员很快识破"这是假人"。

**落地方案**：

- 每个"受训对象"是一个原生生灵：有自己的生理/情绪状态、目标（求生、求救、攻击、拒绝配合）、会和身边其他"灾民"协商分工。
- 教官在控制台注入事件（火势蔓延、有人休克、通讯中断），重规划器让受训对象**真的改变行为**，而不是按剧本走到下一个节点。
- 全程日志自动生成训练评估报告：学员哪一步判断失误、哪个 NPC 的反应被忽视。
- LLM 仅用于让受训对象"说出符合其身份的台词"，但**所有台词背后的情绪与决策由规则内核驱动**，避免 LLM 乱编医学/军事事实。

### 4.5 教育陪伴 / 儿童与老年陪伴

**痛点**：现有陪伴机器人"百科问答"味重，没有"自己的生活"，孩子很快失去兴趣。

**落地方案**：

- 陪伴型生灵有自己的"日常"：早上说饿了要"吃"虚拟能量、下午要和孩子一起完成一个小任务、晚上要"睡觉"。
- 它**不主动教知识**，而是在自己的目标里自然遇到问题（"我想过河但不会游泳"），邀请孩子一起想办法——把教育目标藏在协作任务里。
- **安全兜底**：规则内核硬过滤所有不适合儿童的话题；LLM 输出必须过规则层白名单。这是这类场景与游戏最大的区别。

## 5. 成本结构与 TCO 对比

以"同时服务 1 万 DAU 的游戏 NPC 系统"为例（月度，人民币估算）：

| 方案 | 规则内核 | LLM 调用 | 带宽/服务器 | 合计/月 |
|---|---|---|---|---|
| 纯脚本 NPC | 低（一次性） | 0 | 低 | ~2 万（人力摊销） |
| 纯 LLM Agent | 0 | **30–80 万**（每玩家每小时 0.5–2 元） | 高 | **35–85 万** |
| **本方案（规则+LLM 混合）** | 中（一次性 2–3 人月） | 2–6 万（仅开放对话路径） | 中 | **4–9 万** |

结论：**混合架构的月度成本约为纯 LLM 方案的 1/10**，且延迟从 1–5 秒降到 50ms 以内，行为可审计。

## 6. 18 个月落地路线图

| 阶段 | 时间 | 目标 | 交付物 |
|---|---|---|---|
| **P0 验证** | M1–M2 | 复刻 Monta 闭环到目标业务场景，离线跑通 | 一个垂直场景的可演示原型（类似营地 demo） |
| **P1 内核产品化** | M3–M5 | 把 BDI/目标图/协商/重规划做成 SDK，提供 Unity/UE5 双插件 | SDK v0.1 + 接入文档 + 10 个示例 NPC |
| **P2 LLM 混合** | M6–M9 | 上线 LLM Adapter，覆盖开放对话；建合规词表与行为护栏 | SDK v0.5 + 成本看板 + 审计日志工具 |
| **P3 规模化** | M10–M14 | 单场景 50+ NPC 并发、跨服务器同步、可视化编排器 | SDK v1.0 + 可视化编辑器 |
| **P4 行业复制** | M15–M18 | 从主行业复制到第二、第三行业（文旅 / 仿真 / 陪伴） | 行业方案包 + 案例白皮书 |

## 7. 风险、伦理与合规

| 风险 | 应对 |
|---|---|
| **被误读为"AI 有意识"** | 所有对外物料沿用原型作者声明：行为像活物 ≠ 有意识；用户协议与"关于"页明确这是软件智能体 |
| **LLM 幻觉导致 NPC 说出事实错误/违规内容** | LLM 输出在 TTS/上屏前必须过规则层；医疗/法律/儿童场景禁用开放生成 |
| **行为不可预测导致玩家/用户体验失控** | 每个 NPC 有硬约束（不能伤害玩家、不能离开指定区域）；重规划必须经过策略白名单 |
| **数据合规（未成年人、个人信息）** | 陪伴类场景默认不上传语音原文；用户数据本地化 |
| **成本失控** | LLM 调用按 NPC × 时长 × 白名单话题限流；预算耗尽自动降级为纯规则模式 |

| Monta / QY demo 中的行为 | 在本方案中的模块 |
|---|---|
| 两个同伴开场语音协商分工 | `negotiation.py` · 提案-反提案-确认协议 |

| 全程中文语音、离线、无密钥 | `llm_adapter.py` stub + 端侧 TTS 接口 |
| QY 第三人称高保真场景 | L6 表现层（UE5 插件桥接） |

## 9. 立即开始

1. 跑通 `python -m examples.camp_demo`，在终端里复现 Monta 闭环。
2. 选一个你自己业务里的"NPC"，问自己三个问题：
   - 它**今天**的愿望（Desire）是什么？
   - 如果世界突然变了，它**现在**会怎么改计划？
   - 它的决策链路里，**哪一步真的需要 LLM**？
3. 从 L3 自治内核开始接，LLM 留到 P2。
